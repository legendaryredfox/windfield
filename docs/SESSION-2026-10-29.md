## Findings worth remembering

- `World:setContactFilter` is a LÖVE method that windfield proxies, so the filter hook is named `setColliderFilter`. The proxy shadow test caught it.
- Calling the proxied `Fixture:setSensor` on a collider made the solid fixture a sensor and dropped every event (upstream issue 31). `Collider:setSensor` now switches the whole collider: all categories masked on the solid fixtures, events from the sensor fixtures.
- Box2D creates no contact unless one body is dynamic, so sensors on static or kinematic bodies need a dynamic partner. Documented.
- `Contact:setTangentSpeed` takes meters per second. The `conveyor` option is in pixels per second and divides by the meter. The sign is `-speed` for either fixture order because the normal and the relative velocity flip together.
- `love.physics.getDistance`: exact for overlap, containment and tangency; subtracts the polygon skin (0.32 px each, so near misses under about 0.6 px count as hits); only uses child 0 of a chain (chains are tested edge by edge); cheaper than `queryCircleArea` (4.3 ms against 7.8 ms per 2000).
- Near contact the points returned by `getDistance` collapse and float32 noise at large coordinates makes their direction random, so `shapeCast` keeps the normal of the last clear step.
- `love.math.triangulate` accepts either winding but returns wrong triangles for self intersecting polygons instead of failing, so the library checks that itself.
- Box2D moves a body at most 2 meters per step (64 px at meter 32), which caps `moveKinematic`.
- `applyForce`, `getMass` and velocities share the same pixel units: an effector with `gravity = {100, 0}` gives exactly 100 px/s per second.
