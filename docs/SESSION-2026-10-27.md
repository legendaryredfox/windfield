# Session 2026-10-27

What was done to windfield in one working session, why, what was measured, and what is left. The repository state at the end is `master` at `a370357`, tagged `v0.1.0`, pushed to `legendaryredfox/windfield`.

## Starting point

The repository was a fork of the archived upstream `a327ex/windfield` (last upstream push 2020). It had no tests, no AGENTS.md, no documentation of supported versions, and a few bugs against current LÖVE and Lua.

## 1. AGENTS.md

Written first, from the AGENTS.md and CLAUDE.md files of the sibling projects in `~/development` (mainly desAnim8, LOVE-WrapLua and carmensandiego_love). It records the layout, the rules (Lua 5.1 to 5.5 common subset, comments only where necessary, no em dashes, owner is the sole author, CRLF line endings preserved, always run LÖVE under `xvfb-run -a`) and the internals of `init.lua`. It was kept up to date as the code changed.

## 2. M0: LÖVE 11.5 and Lua 5.5 compatibility

Targets chosen: LÖVE 11.5 as the runtime, and source that also loads and runs on Lua 5.1 to 5.5 (checked with a mocked `love`, since LÖVE cannot run Lua 5.5). LÖVE 12 is out of scope: it is unreleased and merges Fixture into Shape.

An audit (reading the source and loading each file on each interpreter) found:

| Finding | Fix |
|---|---|
| `mlib.lua` assigned to a `for` loop variable, a compile error on Lua 5.5 | use a separate local |
| bare `unpack` in `init.lua`, missing on Lua 5.2+ | `local unpack = table.unpack or unpack` |
| `World` was a global | made local |
| `World:draw` used 0 to 255 colors; LÖVE 11 takes 0 to 1, so debug drawing was always white | convert, `draw(alpha)` keeps its 0 to 255 argument |
| `newChainCollider` passed arguments to `newChainShape` in the wrong order; the failed call also left a body with no fixtures, which crashed `World:update` | argument order fixed (confirmed in real LÖVE first) |
| area queries raised an error when a circle collider was in the region (`CircleShape` has no `getPoints`) | circle shapes tested by center and radius |

A test setup was added: `tests/mock_love.lua` and `tests/run.lua` (mocked `love`, four interpreters) and `tests/smoke/` (real LÖVE 11.5 under xvfb, with a screenshot of the debug drawing that was inspected for colors and alpha).

## 3. Planning and research

`SPEC.md` and `PLAN.md` (gitignored, local) hold the roadmap: groups A (performance and correctness), B (features), C (ecosystem), D (ideas from the survey), with phases, acceptance criteria and an index of every suggestion.

Research done:

- The upstream issue list: #28 (circle queries) and #25 (global `World`) are fixed here; #31 (sensors), #24 (destroyed contact), #17 (STI) and #2 (effectors) are on the roadmap.
- Other libraries: breezefield (Box2D wrapper, active), bump, HC, slick, Strike, loveblobs, sti-windfield. Notes are in `SPEC.md` section 6.
- Jolt Physics: 3D C++ engine, no Lua binding listed, has `Plane2D` (verified in its source). Assessed as a source of ideas (shape casts, character controller, ragdolls, contact filter, snapshots), not as a backend.
- Benchmarks of windfield against raw `love.physics` only. The runner for breezefield, bump, HC and slick exists in the scratchpad but was not run: the permission system blocked executing third-party library code. This needs the owner's decision (SPEC Q4).

## 4. Phase 0: benchmark harness

`tests/bench/` (windfield versus raw `love.physics`, median of 3 runs, markdown table via `table.lua`) and `tests/run_all.sh`. The baseline it recorded is in `CHANGELOG.md`.

## 5. Phase 1: foundations (released as 0.1.0)

Every item was test first. Measurements are LÖVE 11.5 under xvfb, 2000 bodies.

| Item | Change | Result |
|---|---|---|
| A3 | shape built before body in `Collider.new` | a failing constructor leaves no body behind |
| A1 | methods resolved through a cached `__index` instead of about 100 closures per collider | memory per collider 12.8 KB to 1.9 KB, create 72 ms to 37 ms |
| A2 | lazy, dirty-tracked event tables | idle update 4.8 ms to 0.23 ms, idle garbage 532 KB to 0 |
| A4 | existing colliders re-masked when a class is added | verified in real LÖVE (collider passes through an ignoring class added later) |
| A8 | one shared query list and callback, per-query class set, each shape tested once, bounding box accept and reject for rectangle queries | rectangle queries 520 ms to 293 ms |
| A9 | query rules pinned in `tests/fixtures/query_cases.lua` and documented | an area entirely inside a polygon collider is not returned; circle colliders are returned for any overlap |
| A6 | collision data carries `nx`, `ny`, `x1`, `y1`, `x2`, `y2` | readable after the step in real LÖVE |
| A5 | `getEnters`, `getExits`, `world:onEnter`, `world:onExit`, stay tracked from events | a bug found on the way: a class listed itself twice in its own event lists, doubling same-class events |
| A7 | `Collider:destroy` during the step is deferred until the step ends | LÖVE 11.5 already defers the body itself; the gain is a complete collider for the rest of the step |

A8 missed its 5x target (1.8x). The remaining cost is MLib's exact test on partly overlapping shapes, and replacing it would change which edge-touching cases hit. That is deferred to feature D3, which defines the rules first. Results were kept identical: 1200 random queries are compared with a frozen copy of the old implementation in `tests/reference_queries.lua`.

README gained the new methods and the query rules, and its table of contents was checked (four old broken links fixed). `wf._VERSION` is `'0.1.0'` and `CHANGELOG.md` has the before and after table.

## How to run things

- `sh tests/run_all.sh`: mocked suite on every installed interpreter, then the smoke script under xvfb.
- `xvfb-run -a sh tests/bench/run.sh --table`: benchmark.
- Push needs the owner key: `git push git@github-legendaryredfox:legendaryredfox/windfield.git <ref>` (the default SSH identity is a different account).
