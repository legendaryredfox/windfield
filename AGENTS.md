# AGENTS.md

windfield: physics module for **LÖVE 11.x** that wraps `love.physics` (Box2D) with collision classes, enter/exit/stay events, area queries and joints. MIT, copyright SSYGEN. Consumers copy the `windfield/` folder into their game and `require 'windfield'`.

## Layout

- `windfield/init.lua`: the whole library (~930 lines). Order: `wf.newWorld`, `World` class (setup, collision classes and masks, collision callbacks, collider factories, area queries, joints), `Collider` class, then `wf.World = World` / `wf.Collider = Collider` and `return wf`.
- `windfield/mlib/`: vendored MLib (math and shape intersection), exposed as `wf.Math`. Used by the `query*Area` functions (`polygon.getCircleIntersection`, `polygon.isPolygonInside`, `polygon.getCentroid`, `line.getLength`). Third-party code: do not edit except to apply a fix that cannot live in `init.lua`; keep its `LICENSE.md`.
- `README.md`: Quick Start, tips, and the full API reference (one section per `World` and `Collider` function, with a table of contents at the top).
- `types/windfield.lua`: LuaLS type definitions (`---@meta windfield`) for the whole public API, and `.luarc.json`, the language server config (Lua 5.5, LÖVE 11 library, `types/` as a library, `tests/` ignored).
- `tests/run.lua` (mocked `love`, `tests/mock_love.lua`), `tests/smoke/` (real LÖVE script, run by `run.sh`), `tests/bench/` (benchmark and table formatter), `tests/run_all.sh`.
- `.github/workflows/test.yml` (jobs `unit`, `lint`, `rockspec`, `smoke`), `.luacheckrc`, `windfield-scm-1.rockspec` (modules `windfield` and `windfield.mlib.mlib`).
- No build step and no dependencies other than LÖVE.

## Rules

- **Targets: LÖVE 11.5 and Lua 5.5.** Runtime is LÖVE 11.5 (LuaJIT 2.1, Lua 5.1 semantics); the source must also load and behave correctly on Lua 5.5, so write the common subset of 5.1 to 5.5. Get `unpack` with `local unpack = table.unpack or unpack`. Never assign to a `for` control variable (error in 5.5), no `loadstring`, `setfenv`, `getfenv`, `table.getn`, `math.pow`, `//`, bitwise operators, `goto`, `<const>`, `<close>`, and never name an identifier `global`. Use only `love.*` APIs that exist in LÖVE 11.5, with no deprecated calls. LÖVE 12 is out of scope (it merges Fixture into Shape).
- The module is loaded as `require 'windfield'`; `local path = ... .. '.'` in `init.lua` resolves `mlib` relative to wherever the folder lives. Keep requires relative to `path`, never hardcode `windfield.`.
- Public API uses `camelCase` methods (`newRectangleCollider`, `addCollisionClass`); fields and locals use `snake_case` (`collision_class`, `box2d_world`). Match the surrounding style (4-space indent, single quotes mostly).
- Keep the module free of globals: `World` and `Collider` are `local` and exposed as `wf.World` and `wf.Collider`. `tests/run.lua` checks this.
- Underscore prefix (`_queryBoundingBox`) marks internal functions. Anything else on `World`/`Collider` is public and must be in the README reference.
- Code comments only where necessary: a comment must explain a non-obvious why. No comments that restate the code, no section banners, no commented-out code.
- LuaLS annotations live in `types/windfield.lua`, not in `init.lua`, so the source keeps its comment rules. Every public change (new method, argument, `settings` key, event field, class option) also updates `types/windfield.lua`: `---@param`, `---@return`, `---@class` with the same names as the README. Check with `~/.vscode/extensions/sumneko.lua-*/server/bin/lua-language-server --check . --configpath .luarc.json --checklevel Warning`: `types/` must report nothing. `init.lua` and `mlib/mlib.lua` still report 7 known warnings (`__index` of LÖVE userdata, `ipairs` over a mixed `ignores` entry, and the deprecated `unpack` fallback that Lua 5.1 needs); do not add `---@diagnostic` comments for them.
- Every public change updates `README.md` (signature heading, text, and the table of contents entry). Heading anchors in the table of contents must match the headings.
- Keep backward compatibility with existing user code: argument order, `settings` table keys (`collision_class`, `body_type`), event table shapes, and default values are API.
- Verification: `lua tests/run.lua` (mocked `love`, from the repo root) must pass on `luajit`, `lua5.1`, `lua5.4` and `lua` (5.5). Always run LÖVE under `xvfb-run -a` (never on the real display). `xvfb-run -a sh tests/smoke/run.sh` runs the real LÖVE 11.5 smoke script (needs `love`); it prints `ok`/`FAIL` lines, any deprecation warning, and writes a debug-draw screenshot to the LÖVE save directory (`~/.local/share/love/windfield-smoke/smoke.png`). New behavior gets a test in `tests/run.lua` first. `sh tests/run_all.sh` runs the mock suite on every installed interpreter and the smoke script in one go. `xvfb-run -a sh tests/bench/run.sh --table` runs the benchmark against raw `love.physics` (record before and after numbers in `CHANGELOG.md` for performance work).
- Lint: `luacheck windfield tests` must report nothing (`types/` and `windfield/mlib/` are excluded in `.luacheckrc`). Install with `luarocks --lua-version 5.1 --local install luacheck LUA_INCDIR=/usr/include/lua5.1` and run it from `~/.luarocks/bin` with `eval "$(luarocks --lua-version 5.1 path)"`. CI runs the same command.

## Internals

- **Units**: the meter is global to LÖVE; coordinates passed to the API are in pixels. `World.new` sets it to `options.meter` when given, otherwise to 32 only for the first world created (module local `meter_initialized`), so a later world never resets it.
- **`wf.newWorld(xg, yg, sleep)`**: builds the `World`, registers the four contact callbacks (`collisionOnEnter/Exit/Pre/Post`) on the Box2D world, calls `collisionClear()`, adds the `'Default'` collision class, and proxies every Box2D world method onto the `World` (`world:setGravity(...)` forwards to `world.box2d_world`), except `update`, `destroy`, `type`, `typeOf` and metamethods.
- **Collision classes**: `addCollisionClass(name, {ignores = {...}, enter = {...}, exit = {...}, pre = {...}, post = {...}})`; adding a duplicate name raises an error. Unless `setExplicitCollisionEvents(true)` was called before, every class gets `enter/exit/pre/post` lists containing all classes (old and new), so events are on by default. `collisionClassesSet()` then runs `generateCategoriesMasks()` (groups classes with identical incoming-ignore sets into one Box2D category; `ignores` supports `'All'` and `except = {...}`), rebuilds the `collisions.on_enter/on_exit/pre/post` tables, and clears events.
- **Sensor vs solid events**: a pair of classes where either `ignores` the other does not collide physically, so its events are delivered from the **sensor** fixtures (`.sensor` tables); all other pairs use the solid fixtures (`.non_sensor`). `isCollisionBetweenSensors` decides, memoized in `is_sensor_memo`. `World.collisionOnEnter/Exit/Pre/Post` check `fixture:isSensor()` on both fixtures and dispatch accordingly. A sensor collider (`Collider:setSensor(true)`, the `sensor` setting, or a class with `sensor = true`, which `classIgnores` treats as `ignores = {'All'}`) has `sensor_mode` set, its solid fixtures get a mask of all 16 categories (`applyMask`, the only place masks are applied) and its events come from the sensor fixtures; for those contacts `emitCollisionEvents` also walks the `non_sensor` class pair list. `Collider:setSensor/isSensor` override the proxied Fixture methods on purpose. Box2D creates no contact unless one body is dynamic, so static or kinematic pairs report nothing (documented in the README).
- **Collider construction**: `Collider.new(world, type, ...)` takes positional args per type; the last arg is the optional `settings` table. Keys: `collision_class`, `body_type`, `object`, `sensor`, the body keys (`bullet`, `fixed_rotation`, `gravity_scale`, `linear_damping`, `angular_damping`, `sleeping_allowed`, `active`, `angle`) and the solid fixture keys (`restitution`, `friction`, `density`, which also resets the mass). `checkSettings` raises on any other key before the body exists; add new keys to `body_settings`/`fixture_settings` (or `checkSettings` for special ones) and to the README list.
  - `Circle (x, y, r, settings)`.
  - `Rectangle (x, y, w, h, settings)`: `x, y` is the top-left corner, body is created at the center.
  - `BSGRectangle (x, y, w, h, corner_cut_size, settings)`: octagon with cut corners.
  - `Polygon (vertices, settings)`, `Line (x1, y1, x2, y2, settings)`, `Chain (vertices, loop, settings)`.
  - Each collider gets a `'main'` shape, a solid fixture and a duplicate **sensor** fixture on the same shape. Both fixtures hold the collider as userdata (`fixture:getUserData()`), and the callbacks read it back. `addShape(name, type, ...)` / `removeShape(name)` add and remove extra shape+fixture+sensor triples keyed by `name`.
  - Body, fixture and shape methods are resolved lazily through `__index` (`newProxyIndex`, cached per shape type, shared by all colliders): shape wins over fixture over body, and class methods win over proxies. `destroy`, `type`, `typeOf` and metamethods are excluded. `tests/fixtures/proxy_keys.lua` lists the names that used to be instance keys; the smoke script checks they still resolve.
- **Events**: `collision_events[other_class]` lists are created lazily by `addCollisionEvent` (called from the callbacks), which also tracks `collision_stay` and records the collider in `world.dirty_colliders`; `World:update` clears only those colliders before the step. Events carry a copy of the contact geometry (`nx`, `ny`, `x1`..`y2`) because LÖVE invalidates the contact after the step. `enter/exit(class)` read the lists; `getEnters/getExits` return all events. `stay` comes from `collision_stay`, which `liveStay` prunes of destroyed colliders. `World:onEnter/onExit` handlers get events recorded in `world.step_events` and run at the end of `World:update`; same-class pairs are reported once (`a.id < b.id`).
- **Fixed step**: `World:step(dt)` accumulates time and calls `update(fixed_dt)` up to `max_steps` times (excess time is dropped), `getAlpha()` is `accumulator / fixed_dt`. Colliders marked with `setInterpolated` live in `world.interpolated`; `step` calls `_snapshot()` on them before each update and `getRenderPosition/Angle` blend the snapshot with the current state. `_destroy` removes the collider from the set. `update(dt)` alone never refreshes snapshots.
- **Raycast**: `World:raycast` uses a per-call closure on `box2d_world:rayCast`. It returns `-1` for fixtures it skips (no userdata, destroy pending, sensor fixture, class not allowed), `1` in `'all'` mode (sorted by `fraction` afterwards) and the fraction in `'closest'` mode so Box2D clips the ray. Sensor colliders are hit like any other collider; callers filter by class.
- **Contact rules**: the pre-solve path (`World.collisionPre`, solid fixtures only) runs, in order, `contactRejected` (the `setColliderFilter` hook, also called on begin contact; a rejected contact is remembered in the weak `filtered_contacts` so its exit event is dropped too), `applyContactRules` (only when `has_contact_rules`, i.e. some class has `one_way` or `conveyor`) and then the user `preSolve` handlers, which can override with `contact:setEnabled(true)`. `World._oneWaySolid` is the pure decision (contact normal from platform to other against the platform vector, relative velocity along it, 1 px/s tolerance). Box2D re-enables a contact every step, so the rules run on every pre-solve. `Contact:getNormal` points from fixture A to B and Box2D drives the relative velocity of B along `(n.y, -n.x)` to the tangent speed, which makes the sign `-speed` for either fixture order; LÖVE takes the tangent speed in meters per second, so `conveyor` (pixels per second) is divided by `love.physics.getMeter()`. `World:setContactFilter` belongs to LÖVE and is proxied, which is why the hook is called `setColliderFilter`.
- **Collider callbacks and draw**: `Collider:onEnter/onExit` register handlers in the same `world.collision_handlers` list as `World:onEnter/onExit`, with a `collider` field; `_dispatchCollisionEvents` calls them only when the event receiver (`collider_1`) is that collider and the other collider's class matches, and `Collider:_destroy` removes them. `World:draw` draws one body at a time (`drawBody`): a collider with a `draw` function (an instance field, not a proxied method) replaces the debug shape; `setDrawOrder` sets `has_draw_order` on the world, which makes `draw` sort the bodies by order and then creation index. Debug drawing skips the duplicate sensor fixture of a collider.
- **queryShape**: exact overlap through `love.physics.getDistance`. The query shape lives on a static body of a hidden `love.physics.newWorld` (`query_world`, created on first use, destroyed with the world) so it never touches the game world; a fixture is created and destroyed per call. `getDistance` only uses child 0 of a shape, so `ChainShape` candidates are tested edge by edge (`chainOverlaps`, with `getChildEdge` on the second hidden body `query_chain_body` placed at the chain body) after a per child bounding box check. Hit means distance `<= 0`; LÖVE subtracts the polygon radius (0.32 px) so near misses under about 0.6 px count as touching. The cases are pinned in the smoke script (`queryShape:` checks), the mock `getDistance` only compares bounding boxes.
- **shapeCast**: conservative advancement on top of `queryShape`'s hidden query body (`newQueryFixture`). Candidates come from `queryBoundingBox` over the start and end boxes; for each solid fixture (each edge of a chain, as in `chainOverlaps`) `advanceToHit` moves the query body, asks `getDistance` for the gap and the nearest points, and advances by `gap / (cos to the separating plane * length)`; a hit is `distance <= 1e-3` (inside LÖVE's polygon skin, so the fraction is up to 0.3 px early), a miss is `t > 1`, a non positive closing rate or 32 iterations. The normal is kept from the last step with a clear separation because near contact the two points collapse and float32 noise at large coordinates makes their direction random. Expected fractions are hand computed in the smoke script (`shapeCast:` checks).
- **Character helpers**: `Collider:getGround` walks `body:getContacts()` (touching, enabled, no sensor fixture), turns the contact normal into one pointing from the ground to the collider (`contact:getNormal` points from fixture A to B) and keeps the contact with the largest dot product against the up vector (opposite of the world gravity, or `(0, -1)`), within `max_slope`. `moveKinematic` and `driveTo` only set velocities, so Box2D's 2 meter per step translation cap applies (checked in the smoke script). `wf.newTimer` is a plain countdown table with no world state.
- **Concave polygons**: `World:newConcavePolygonCollider` runs `polygonPoints` (validation, `segmentsTouch` for self intersection because `love.math.triangulate` returns wrong triangles instead of failing for them, verified in LÖVE 11.5), `love.math.triangulate` (works for either winding), then `convexPieces` (Hertel-Mehlhorn on vertex indices; triangles are made counter clockwise and degenerate ones dropped, two pieces merge when they share an edge, the union is convex and has at most 8 vertices). The first piece goes through `Collider.new` as a normal `'Polygon'` and the rest through `addShape` as `part2`, `part3`...; if one fails the collider is destroyed again. The mock suite uses an ear clipping `love.math.triangulate` and the mock `newPolygonShape` rejects non convex or over 8 vertex polygons like LÖVE.
- **Effectors**: `World:addEffector` stores a record in `world.effectors` and returns a handle table of closures (`setEnabled`, `isEnabled`, `setGeometry`, `destroy`). `World:update` calls `_applyEffectors` before the Box2D step: per effector a `queryBoundingBox` over the region bounds collects candidate colliders (`effector_callback` into the shared `effector_candidates`), then dynamic bodies of allowed classes whose center is inside the region (`regionContains`) get one `applyForce` with the sum of the effects (`_applyEffector`). `gravity` is `mass * a`, `drag` is `-k * mass * v`, `buoyancy` is `submerged * mass * |g| * fluid / own density` against the world gravity, with `submerged` from the union of the solid fixture boxes against `level`. LÖVE's `applyForce` is in the same pixel units as velocity and `getMass`, verified in the smoke script (gravity 100 gives exactly 100 px/s per second).
- **Joints and builders**: `addJoint` takes a trailing plain table as options (`limits`, `motor`, `frequency`, `damping_ratio`; keys are checked before the LÖVE joint is created, and `applyJointOptions` picks the setter by joint type, e.g. the spring setters for `WheelJoint`), and the `new<Type>Joint` constructors are generated from one list. `newRope`, `newChain` and `newBridge` share `_newLinked`: rectangles (or circles for chains) along the line, revolute joints at the boundaries, optional static pins or given anchors; `newRagdoll` builds named parts and `addJoint` definitions. All return an assembly (`newAssembly`) with `destroy()`, and `buildSafely` destroys a half built assembly when a part fails. Box2D removes a body's joints when the body is destroyed, so `destroy` removes joints first (`isDestroyed` guard).
- **Pools**: `World:newPool(factory, reset)` returns a table with `get`, `release`, `size` and `clear`. Released colliders get `setActive(false)` (no contacts, not in the broadphase, so no queries or events), zeroed velocities and cleared event tables, and wait in `pool.free`; `pooled` is set on the collider (`isPooled`). Releasing while `world.stepping` queues `{pool, collider}` in `world.release_queue`, which `World:update` drains after the destroy queue. `get` skips colliders destroyed meanwhile; `reset` is not called for freshly created colliders. `World:draw` skips bodies that are not active. Deactivating a body ends its contacts, so touching colliders do get an `exit` event.
- **Snapshot**: `World:snapshot` reads every body that has a live windfield collider (`colliderOfBody`, first fixture user data) into a table keyed by `collider.id`; `World:restore` writes the entries back (pool membership first through `pool:release` or `pool_methods:_take`, then active flag, class, pose, velocities, awake, and it clears the collider's event tables) and returns the sorted ids it could not find. LÖVE 11.5 does not expose contact impulses, so a restore on top of contacts leaves Box2D's stale warm start in place; measured in LÖVE 11.5: free flying and simple scenes diverge by 0, a 60 body pile by about 100 px after 30 steps. Two separately built identical worlds stepped with the same dt gave exactly equal positions after 400 steps, in one process and across processes. The replay recorder from SPEC C1 was deliberately not built because replaying through `restore` cannot be exact (and ids are random per build); the README documents the rebuild and replay inputs recipe instead.
- **Queries**: `queryCircleArea`, `queryRectangleArea`, `queryPolygonArea`, `queryLine` return colliders. Candidates come from `_queryBoundingBox` (one shared result list and callback per world, cleared by the caller), are filtered by a per-query class set (`_collisionClassFilter`, nil means all), and each solid fixture (`collider.fixtures`) is tested once. Axis aligned rectangle queries skip the exact MLib test when the fixture's bounding box is strictly inside or strictly apart from the rectangle. `CircleShape` has no `getPoints` in LÖVE 11.5, so circle shapes are tested by center and radius (`fixtureCircle`, `World:_polygonQueryHit`). The rules are pinned by `tests/fixtures/query_cases.lua` (mock suite and smoke) and by a randomized comparison against `tests/reference_queries.lua`, a frozen copy of the pre-optimization code: change the reference only on purpose.
- **Joints**: `addJoint(type, ...)` swaps `Collider` arguments for their `body` (first arg, and second arg if it is a table) and calls `love.physics['new' .. type](...)`, so `'MouseJoint'` becomes `love.physics.newMouseJoint`. `removeJoint` calls `joint:destroy()`. Joints are not tracked by `World`.
- **Destroy**: `Collider:destroy` while `world.stepping` only marks the collider (`destroy_pending`) and queues it; `World:update` finishes the queue after the step (`Collider:_destroy` clears userdata, nils shapes/fixtures/sensors and destroys the body). `World:destroy` destroys every collider, then any remaining joints, then the Box2D world, and sets `box2d_world = nil`. Do not use a collider or world after `destroy`.

## Pitfalls

- `is_sensor_memo` is reset and existing colliders are re-masked whenever a class is added (`collisionClassesSet`), so adding classes late is supported; it costs one pass over all bodies.
- A collision class name must exist before `setCollisionClass`; the code raises `error(...)` otherwise. Keep error messages in that form.
- Collision callbacks run inside `world:update` and Box2D forbids changing the world there. `Collider:destroy` defers itself during the step; library code must still not create colliders or change bodies from the `enter/exit/pre/post` paths, and users should do that work in `World:onEnter/onExit` handlers or after `update`.
